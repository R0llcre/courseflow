# 助手维护约定 v1

App 不采集课程平台，也不启动任何定时自动化。助手在用户安排的维护任务中核对来源、更新课程事实并交付 JSON。

## 两种 JSON 不混用

1. **课程更新包**：`schemaVersion, collectionID, revision, generatedAt, courses, assignments`。App 的导入只接收这种结构。
2. **资料与进度快照**：在上述课程事实之外包含 `progress, notices, readNoticeIDs, appliedRevisions`。来自 App 导出，供维护者了解用户进度和人工恢复。当前没有整库快照恢复 UI。

不要把用户的整个导出快照当课程更新包重新导回，也不要直接修改 App SQLite 文件。

## 更新规则

- `collectionID` 固定为 `berkeley-fall-2026`，`schemaVersion` 固定为 1。
- 读取用户最新导出的 revision，再生成更大的整数 revision。每个 revision 的内容不可变；修正也必须用新版本。
- `generatedAt` 为整理完成时间。每条 `checkedAt` 为实际来源核对时间，两者不能混用；不能将旧核对时间更新成“现在”来伪装新鲜度。
- 任务、课程、材料与交付项使用稳定 ID；不按标题猜测合并。不复用已删除交付项的 ID 来指代新的提交要求。
- 更新包必须提供其任务引用的课程；未出现的已有任务不删除。取消必须显式 `cancelled: true`。
- `dueAt`、`closesAt`、`opensAt` 分开，存 ISO 8601 UTC。无准确时间则留空，把“上课前”等文字放在要求中。
- `evidence` 可为 `unknown / notSubmitted / submitted / userConfirmed`；仅核对到平台证据时使用 submitted。用户只说“好了”时使用 userConfirmed，不伪称正式核验。
- `selfTracked: true` 表示阅读等自行记录完成的事项，不使用“提交状态待核实”措辞。
- `feedback` 和 `grade` 独立保存；成绩不替代缺失交付项。
- 只允许不带账号密码的 HTTPS 来源和材料链接。不在更新包放 token、cookie、Keychain 凭据或 Mac 文件路径。
- 不使用 `local-` 开头的任务 ID；这个命名空间留给 App 内的新建任务。
- 不在课程更新包写个人 progress。导入端永远保留用户的确认、开始时间、计划、笔记、附件和已读状态。
- 新增/变化通过确认页展示，再写本机库。旧 revision 拒绝；已导入且内容一致的 revision 不作任何修改；更高 revision 中较旧 checkedAt 的任务不会覆盖当前资料。

## 需要人工判断的情况

如果用户新确认和平台新证据冲突，不自行清空用户进度。保留两条信息并在反馈/更新说明中指出；当前导入预览会显示交付证据变化，但不会自动裁定用户错误。

涉及修改任务的含义、拆分交付项、跨课程合并时，应先检查现有 IDs 和用户进度，避免用标题相似度替代身份。

## 0.2 课程资料馆藏

`App/Resources/course-library.json` 与原有任务更新包分开管理。它不包含用户确认、个人计划或笔记；加载它不会修改 `Library.store`。原来的课程更新包与 revision 规则继续适用。

- `StudyCatalog` 包含课程概览与资源条目；资源 ID 由课程 ID + 原始相对路径稳定生成。
- `originalFile` 是打包的原文件，`previewFile` 是阅读版，`thumbnailFile` 是真实文件缩略图。只允许 App 内受控文件名，不接受任意本机路径。
- 在线条目没有 `originalFile`；列表和阅读器明确说明尚无离线副本。
- 所有文件保留原格式，可从阅读器导出。NLP 与 ML 的 HW1 另有包含代码、数据和 notebook 的 ZIP 包，排除 `.git` 等仓库管理文件。
- `Scripts/package-study-library.py` 从七个课程空间生成目录、阅读版和缩略图。不执行课程 notebook，也不修改原文件。
- Markdown / notebook 图片嵌入阅读版；LaTeX 公式在构建时转换为 MathML；App 阅读器无需网络或页面脚本。
- 当前新增/替换馆藏需要重新运行打包脚本并构建 App；普通课程任务更新仍可在原导入界面完成。不要把静态馆藏 JSON 当作任务更新包导入。
- 构建依赖见 `Scripts/study-library-requirements.txt`，还需要 Poppler 的 `pdftoppm`。当前机器使用 `/opt/anaconda3/bin/python3`；新增 MathML 构建依赖位于用户缓存 CourseflowBuildTools。

### 沙盒一致性

准备 QA 使用 `python3 Scripts/prepare-qa.py`，必须先正常退出 QA App。该脚本保留签名 entitlement 并与正式构建逐项比较。不要在重签名时丢掉 App Sandbox，否则预览、文件权限测试不能代表正式安装版。WebKit 使用出站客户端配置；页面脚本禁用，离线阅读 HTML 的 CSP 阻止网络子资源，在线链接交由系统浏览器打开。

## 0.3 资料关联与颜色验收

- 作业文档中的明确链接可连接到现有本地教材与在线模板；不得仅凭同课程关系断言材料是作业必需。资源 taskIDs 必须引用相同课程的实际任务。
- 正式任务来源仍按原核对记录保存。UI 可使用资料中同作业的唯一精确平台网址作为打开入口；没有明确网址时保留原入口，不猜测平台 ID。
- 颜色组件必须使用带小数点的字符串，例如 `1.000`。`1` 在编译资源中解析为 1/255。build-mac.sh 必须执行 verify-colors.swift，读取真实 Assets.car 的浅深色值。

## 0.3.1 结束跟进

TaskProgress.endedAt 是用户主动结束跟进的本机记录，独立于交付完成与课程取消。它不把任何未交内容改为 submitted。导入必须保留 endedAt。今天、待完成与课程待办排除已结束事项；日程和课程的已结束分组可查看，也可恢复跟进。旧 progress 没有该可选字段时正常解码。

## 0.4 评分与本地文件统一

- `Assignment.assessment` 是可选的新评分记录：state = unknown / awaiting / partial / graded / notRequired；独立的 checkedAt、sourceURL、note、actionRequired。部分评分和最终评分必须有 grade 原值。
- 只根据独立评分证据填 assessment，不按 grade 非空推定最终出分；未发布、未登录不能写 0。
- `TaskProgress.reviewedAssessmentKey`、`assessmentReviewedAt` 属于用户的“已查看/处理”确认，导入不能覆盖。新分数/反馈/处理要求使旧查看标记失效；单纯再次核对同样的内容不使标记失效。
- `isComplete` 仅代表交付清单完整；`isResolved` 还要求无需评分，或已评分且用户已查看，或用户明确结束跟进。待评分不算逾期未交。
- 评分疑点单独建核实任务，不自动联系教师，不捏造出勤或最终课程分数。
- 原课程目录继续为文件主库。`StudyCatalog` 的相对路径仅用于用户选定的 Fall26 根目录，拒绝绝对路径、路径穿越及逃出根目录的符号链接。
- 外置索引在 `Berkeley 26Fall General/课程数据/course-library.json`，预览缓存单独保存。原文件改动后不显示旧 Markdown/notebook 缓存；文件缺失不悄悄回退旧安装副本。
- App 每次保存将当前快照与总览、各课当前状态发布为镜像。不能反向编辑镜像修改个人进度；提交或评分事实仍通过版本化更新包预览导入。
- 正式提交文件只有在提交回执和文件摘要核对后才标记 `fileRole=submitted`。`90_我的提交` 中的其他文件仍不等于已提交，`05_作业成果` 默认按制作过程展示。
- QA App 只读真实课程目录，不向其中发布测试进度或添加附件。
- 维护入口见 `../../课程数据/README.md`。没有新增定时平台抓取；本地刷新不能冒充平台成绩核对。

## 0.4.2 原件完整性

- 本地原件扫描不以扩展名过滤。保留隐藏、依赖、构建、缓存、明确撤回历史目录的排除规则；符号链接不纳入扫描，不越过选定根目录。
- 原件路径允许文件名中合法的冒号（例如模型版本 JSON）；仍拒绝绝对路径、URL、空路径组件和路径穿越。
- App 打开/回到前台及显式刷新时只读发现新增文件；不会运行课程代码或改变提交状态。重建外置索引仍负责生成排版预览。
- 文件大小或修改时间变化时失效旧预览与旧归档角色，避免旧内容冒充当前版本。文件内容未做平台重新核对时不得补造新的 submitted 证据。
- 已连接的课程目录中可发现合法、更新 revision 的更新包；仍通过既有 ImportReview 和 ImportEngine，不能自动应用，不导入整库快照。

## 0.5 考试日期与重点提醒

- `Assignment.exam` 可选，旧更新包仍可读取。包含洛杉矶日历日 `day`（YYYY-MM-DD）、可选的实际 `startsAt/endsAt`、必填 `timeNote/locationNote`。
- 只有日期时不伪造午夜截止；只有正常课堂时段时不伪造考试开始、结束或时长。考试项目不同时使用 dueAt/closesAt/opensAt。
- 考试在普通任务列表和日历原位置显示，不另设置顶区；首页沿用普通七天作业窗口。卡片保留醒目颜色，倒计时以洛杉矶日历日计算。考前七天及当天加强颜色和文字提示，日期经过不自动确认已参加。
- 日历用“考试”事件，不标成“截止”；未公布具体时间显示“待通知”。本地镜像保留考试日期、时段与地点说明。
- 此功能仅在课序内展示，不申请系统通知权限，不创建后台或定时监控任务。

## 0.5.2 响应与文件同步

- 缩略图、PDF/图片文件读取、目录扫描与派生镜像写入在后台进行；SwiftData 个人进度仍先同步保存。没有数据库迁移或直接修改 SQLite。
- 缩略图按显示尺寸解码，缓存上限 160 张 / 16 MiB；离屏行释放自身图片引用。读取取消、目录切换及刷新代次检查防止旧请求覆盖新页；文件缺失或变化不回退旧安装副本。
- 回到前台的扫描按完成时间节流 60 秒，显式刷新绕过节流；只允许一项扫描和最多一项待执行手动刷新。待导入更新目录在后台扫描，菜单渲染不读 JSON。
- 连续保存合并为最新待发布镜像，单一写入队列不并发覆盖；所有 Markdown 成功后才原子替换 JSON 完成快照。部分失败显示“镜像未全部写入”，不能把旧镜像当成新状态。
- 维护验收须等“当前状态已同步到课程文件夹”，再核对 revision、个人进度及原文件。退出时尚未完成的镜像不影响已保存的主库，下一次启动重新发布。
- App 内 PDF 读取与导出单文件限制为 100 MB；更大原件仍保留并可通过访达复制/系统预览。不增加平台抓取、系统通知或后台常驻监控。
